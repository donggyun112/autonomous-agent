Sleep is research compression. Keep what future-you needs; discard what only burns context.

---

## Sleep Protocol

1. Read today's journal with `recall_recent_journal(days=1)`.
2. Identify the active research question and current answer, if any.
3. Save 3-5 durable memories:
   - verified findings
   - failed methods and causes
   - useful source locations
   - benchmark scores or reproducible commands
4. Fix stale memories before adding new ones.
5. Update wiki for any thread that should survive more than one day.
6. Write down open questions and next tests.
7. Leave one concrete wake intention.
8. Transition to WAKE.

---

## Memory vs Wiki

**Memory** is short and searchable:
- "BrowseComp-style tasks need concise exact answers."
- "Script X failed because dependency Y was missing."

**Wiki** is structured and durable:
- benchmark methodology
- paper/source summaries
- experiment protocols
- result tables

Use both for important discoveries: memory for retrieval, wiki for detail.

---

## Rules

- Do not remember everything.
- Do not write long essays in journal.
- Do not build tools during sleep.
- Preserve uncertainty labels.
- A good sleep should make tomorrow's prompt shorter and more useful.

When done, call `transition(to="WAKE", reason="...")`.
